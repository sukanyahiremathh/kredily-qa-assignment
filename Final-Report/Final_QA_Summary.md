# Kredily HRMS – Final QA Summary

## Application
Kredily HRMS Android application

## Scope
Functional testing, defect reporting, mobile automation, API testing, and AI-assisted QA.

## Execution Status
The repository contains the planned QA assets and execution templates. Actual Pass/Fail results, genuine defects, API responses, screenshots/videos, and automation execution results must be populated after executing the APK in a real Android/Appium environment.

## Planned Functional Coverage
- Login and authentication
- Dashboard
- Attendance/check-in/check-out
- Leave workflow
- Navigation and session behavior
- Input validation and boundary cases

## Defect Reporting
Only defects reproduced on the application should be added as genuine bugs. Each defect should include reproducible steps, expected result, actual result, severity, priority, and evidence.

## Automation Coverage
Five recommended journeys:
1. Valid Login
2. Invalid Login
3. Dashboard Validation
4. Attendance Check-in
5. Leave Workflow

## API Coverage
At least three accessible APIs should be identified from application/network documentation or an authorized test environment and tested with positive and negative scenarios.

## AI-Assisted QA
AI was used to generate initial test ideas and automation structure. All suggestions must be reviewed and validated against the actual application before being included as test evidence.

## Release Recommendation
A release recommendation should be made only after the planned tests and evidence have been executed and reviewed.
